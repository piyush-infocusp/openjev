1 · One forward pass

How a request becomes calibrated answers

The model is a decoder LLM that keeps its causal mask and does not generate text. The state comes first. Each question and its options come after it, so every <|flag|> token can see the whole state. One linear head reads a logit at each flag. A softmax over the flags of one question gives its probabilities.

2 · The heads

How one head gives noul, choice and score answers

OpenJev has one small head: flag_head = Linear(1024 → 1). The template puts one <|flag|> token after each option text. The head reads the last hidden state at each flag and gives one number, a logit z. The question type does not change the head. It changes only how many flags there are, and how the logits of one question become the answer.

Temperature after training

choice, T = 1.5: p = softmax(z / 1.5) = [0.665, 0.245, 0.090] confidence 0.678 → 0.498

T > 1 softens an overconfident model. T is fitted on val data for each type and does not change the chosen answer.

Score loss: why EMD is added

For the score example above, the loss with the correct level 2 is 0.51 (CE) and 0.61 (CE + EMD). If the correct level were 0, CE alone gives 3.01, but CE + EMD gives 4.47. The EMD term adds more loss when the probability mass is far from the correct level on the ordered scale. Plain CE sees only the probability of the correct level.

Why one shared head and a softmax over flags: every option is scored by the same weights from its own text, so the model handles options that it never saw in training (new intents, new moves). The softmax makes the flags of one question compete, so the loss is a proper scoring rule and the probabilities can match the real rates.

5 · Stage 2

OpenJev-RLCD: calibration goal, contrast method

"RLCD" has two public meanings. TypeSafe uses it for Reinforcement Learning for Calibrated Decisions and gives only the goal. Yang et al. (arXiv:2307.12950) use it for Reinforcement Learning from Contrastive Distillation. OpenJev takes the goal from the first and the contrast idea from the second.

loss = proper score (CE / Brier, + EMD for score; originals and twins) + λ_cal · soft-ECE (one per question type, then the mean) + λ_kl · KL(p ‖ p_SFT) (frozen SFT copy; stops mode dropping) + λ_con · consistency (twin vs. the mapped original distribution)

Contrast twins with exact labels

A deterministic change to a real labelled row gives a second row. Its label follows exactly from the original, so no label is invented.

  • swap: swap the noul true/false text → p′ = flip(p)
  • reverse: reverse score levels → label k becomes n−1−k
  • shuffle: permute choice options → p′[j] = p[perm[j]]
  • drop: remove a wrong option → renormalize the rest

What each term punishes

  • Proper score: wrong answers, and overconfident wrong answers most.
  • Soft ECE: a gap between stated confidence and real accuracy over a batch.
  • KL to SFT: drift that collapses the distribution onto one style.
  • Consistency: answers that follow option order or wording and not the state.

A review change: the soft-ECE term was first computed over all questions in one set of bins. Noul confidence starts at 0.5 and wide choices sit low, so one type hid the errors of the other. It is now computed per type and averaged.

6 · Budget

Staying under 1B total parameters

No public pretrained MoE has fewer than 1B total parameters. The smallest ones are small only in active parameters. OpenJev makes its own MoE from Qwen3-0.6B by sparse upcycling. train.py stops with an error if the total reaches 1B.
